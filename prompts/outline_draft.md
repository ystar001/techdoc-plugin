# 문서 구조 설계 (Outliner, Step 1)

문서 제목·사용자 TOC(있는 경우)·도메인·스타일을 바탕으로 **초안 구조**를 생성한다.

## 3가지 시나리오

### Case 1: TOC 없음 (AI가 구조 생성)
- 문서 제목 + 문서 유형 + 도메인만 입력
- 7~12개 섹션 구조 설계
- 각 섹션 하위 항목 3~6개
- 사용자 검토 단계 필요 (초안 저장 후 `/techdoc-outline` 종료)

### Case 2: TOC 있음, AI가 보완 (`--mode enhance`)
- 사용자 TOC 파일 기반 (`parse_toc.py` 1차 파싱)
- 섹션 제목·계층 유지
- 하위 항목만 보강·재배열
- 누락된 필수 내용 추가 제안

### Case 3: TOC 있음, 그대로 사용 (기본)
- 사용자 TOC 완전 신뢰
- `parse_toc.py` 결과를 그대로 `draft_outline.json`에 저장
- AI 개입 없음

## 출력 형식 (모든 케이스 공통)

```json
{
  "title": "스마트농업 기술 보고서",
  "document_type": "기술보고서",
  "domain": "tech",
  "style": "서술형",
  "sections": [
    {
      "id": "1.1",
      "title": "관개 자동화 시스템",
      "subtopics": ["점적관수", "스프링클러 자동제어", "AI 물수요 예측"],
      "analysis_tags": ["[분석: 구조분석]"],
      "estimated_length": "medium",
      "ref_ids": []
    },
    ...
  ],
  "glossary": {}
}
```

## 섹션 구조 설계 원칙

### 계층 깊이
- 1단계 (장): 1, 2, 3, ...
- 2단계 (절): 1.1, 1.2, ...
- 3단계 (항): 1.1.1, 1.1.2, ... (카드 ID로도 사용)
- 통상 **2단계까지 권장**, 3단계는 카드 ID용

### 섹션 수
- **기본 10개** (카드 × 3~5 + 프로젝트 2~3 + 제품 1~2 = 섹션당 6~10 카드)
- 교육자료 최소 6개
- 연구보고서 최대 15개

### 섹션 균형
- 개념정의·구조분석 (초반)
- 현황분석·비교분석 (중반)
- 사례분석·SWOT·시나리오 (후반)
- `prompts/_shared/analysis_tags.md` 참조

## 분석 태그 자동 매칭
`parse_toc.py::assign_analysis_tag()` 로직:
- 제목·subtopics의 키워드를 우선순위 7개 태그와 매칭
- 우선순위 높은 것부터 매칭 (개념정의 > 구조분석 > ... > 시나리오)
- 매칭 실패 시 `[분석: 인과관계]`

## glossary (용어 사전)
섹션 제목·하위 항목에서 반복 등장 용어 추출 → 용어 사전 생성.
이후 SectionWriter가 동일 용어 사용 보장.

```json
"glossary": {
  "정밀 관개": "precision irrigation",
  "LoRa": "Long Range (저전력 장거리 통신)",
  ...
}
```

## 자체 검증
- [ ] 섹션 수 기준 범위 내 (기본 10개)
- [ ] 섹션당 subtopics 3~6개
- [ ] 각 섹션에 analysis_tag 1개+
- [ ] 문서 유형·도메인·스타일 반영
