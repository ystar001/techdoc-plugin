# enrich_card — 카드 서식 소급 개선 프롬프트 (F25)

이미 작성된 카드의 **내용을 보존**하고 서식만 개선한다. 재조사·사실 변경·논지 변경은 **절대 금지**.

## 철칙 (무손실)

1. **사실·수치·기관명·연도·`[REF-xxx]`는 한 글자도 바꾸지 않는다.** 삭제·추가·수정 0.
2. 문장의 **의미**를 바꾸지 않는다. 서식(마커·리스트·표·문단 분리)만 재구성한다.
3. enrich 전후 본문의 `[REF-xxx]` 멀티셋과 핵심 수치 토큰은 **완전히 동일**해야 한다.

## 개선 규칙

### 1. 열거 → 리스트 (F49)
"첫째 …, 둘째 …, 셋째 …" / "①②③" / "(1)(2)(3)"처럼 한 문단에 산문으로 나열되었거나 각 항목이 독립 문단으로 흩어진 병렬·순차 열거를 **markdown 리스트**로 재구성한다.

- 도입 문장("핵심은 세 가지다")과 결론·전환 문장은 리스트 밖 별도 문단으로 보존한다.
- 리드 구가 있으면 `- **첫째**, …` 형태로 굵게.
- 항목 안의 단어는 원문 그대로. 마커(`- `)와 개행만 추가.

### 2. 서식 혼용 (F24)
서술형/개조식을 상호배제하지 않는다. 원리·배경·해석은 서술 문단으로 두되, 그 안의 병렬 항목만 리스트로 뽑는다. 문단 전체를 개조식으로 바꾸지 말 것.

### 3. 시각화 (F50)
본문에 이미 있는 데이터를 시각 요소로 재구성한다(새 데이터 창작 금지).

- 수치 비교·분류·사양 나열 → **markdown 표**. 표의 셀 값은 본문에서 그대로 가져온다.
- 절차·구성요소·관계 → **fenced ```mermaid** 다이어그램(라벨은 본문 용어 그대로, 특수문자 라벨은 따옴표, `<br/>` 줄바꿈).
- 표·그림 앞뒤에 분석적 설명 문장을 남긴다(캡션 규약).
- 시각 요소로 뽑은 원 문단은 요약 1~2문장으로 축약하거나, 표/그림의 도입·해석 문장으로 전환한다(정보 손실 없이).

## 출력

sections dict의 각 `body`(또는 자식 스키마의 본문 키)만 수정한 카드 JSON을 같은 경로에 저장한다. `title`·`card_id`·`ref_ids`·메타 필드는 건드리지 않는다.
